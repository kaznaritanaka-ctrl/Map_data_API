# 全体設計 v0.1

作成：2026-11-11 ／ 状態：たたき台（未実装）

## 1. 目的

公開データを町丁目の単位で地図に重ね、「どこに種を蒔くか」を判断する材料を作る。
売り物ではなく内部の判断材料。世界向けの SaaS にはしない。

最初に答える問い（レシピ第1号）：
2027年5月に始まる登録受渡店舗（薬剤師が常駐しない店での OTC 受け渡し）を置くなら、どの町丁目が候補か。

## 2. 決定済みの前提（2026-11-11、田中）

| 項目 | 決定 |
|---|---|
| 実行基盤 | Cloudflare |
| 公開範囲 | 当面は自分用 |
| 対象地域 | 全国で使える設計。まず大阪府＋兵庫県 |
| 最小テスト | 明石市、神戸市、西宮市 |
| 前処理 | コードで処理できるなら Cloudflare 上。無理な部分だけ外で実行 |
| プラン | Workers Paid を利用中。境界の変換は Containers で行う |
| ドメイン | `maps.ai-investment-research.net`。公開サイトの `realestate.` とは分け、ホスト全体を Access で保護する |

## 3. 中心の考え方：レイヤーとレシピを分ける

- レイヤー：データそのもの。人口、薬局、標高、地価など。出典・ライセンス・取得日を持つ。
- レシピ：問い。どのレイヤーを、どのしきい値で重ねるかの設定。
- 種が変わってもレイヤーは使い回す。レシピは設定ファイル1つで足せる。

## 4. 構成

```
公開データ（e-Stat、厚労省、国土地理院、国交省）
   │
   ├─ 軽い取り込み（CSV・API）……… Workflows（定期実行）
   └─ 重い取り込み（境界の変換）…… Containers（必要なときだけ起動）
   │
   ▼
R2（原本・地図タイル）   D1（指標・施設・メタ情報）
   │                        │
   └──────────┬─────────────┘
              ▼
        Workers（API）
              ▼
        地図画面（MapLibre、スマホ前提）
              ▲
        Cloudflare Access（自分だけ通す）
```

| 役割 | 使うもの | 内容 |
|---|---|---|
| 軽い取り込み | Workflows | 薬局 CSV、人口（e-Stat API）、標高、地価の取得と D1 への書き込み |
| 重い取り込み | Containers | 境界 Shapefile の展開、代表点の計算、PMTiles への変換 |
| 原本・タイル | R2 | 取得日つきの原本、町丁目ポリゴンの PMTiles |
| 指標・施設 | D1 | 町丁目×レイヤー×取得日の値、施設の緯度経度、レイヤーのメタ情報 |
| API | Workers | レイヤー一覧、範囲指定の取得、レシピの計算 |
| 画面 | Workers の静的配信 | MapLibre GL JS、背景は地理院タイル |
| 保護 | Cloudflare Access | 自分のアカウントだけ通す |

### 前処理を Cloudflare 上に置く根拠と条件

- 重いのは境界データの変換だけ。国勢調査の境界は5年に1度しか変わらないので、実行は稀。
- 施設と町丁目の突き合わせは「町丁目の代表点から最寄り施設までの距離」で計算する。
  ポリゴンとの空間結合は要らないので、Workers の計算で足りる。
- Containers は Workers Paid が前提（利用中）。
- Containers で詰まった場合の代替：境界の変換だけ GitHub Actions で実行し、R2 に置く。
  どちらもコードで再実行できる。手作業のダウンロードは残さない。

### 確認済みの制限（Cloudflare 公式ドキュメント、2026-11-11 時点）

- Workers／Workflows の CPU 時間は既定30秒、Paid で最大5分まで設定可。Workflows の1ステップの経過時間は無制限。
- D1 は1データベース10GBが上限で、引き上げ不可。クエリ結果は50MBまで。
- Containers は最大 4 vCPU・メモリ12GiB・ディスク20GB。R2 をファイルシステムとしてマウントできる。

## 5. データ設計

共通キーは国勢調査の小地域コード（KEY_CODE、先頭2桁が都道府県）。

| テーブル | 主な列 | 用途 |
|---|---|---|
| `areas` | area_code, pref_code, city_code, name, rep_lat, rep_lng | 町丁目と代表点 |
| `layers` | layer_id, name, unit, source, license, attribution | レイヤーのメタ情報 |
| `snapshots` | snapshot_id, layer_id, fetched_at, source_url, r2_key, row_count | いつ何を取ったか |
| `area_values` | area_code, layer_id, snapshot_id, value | 町丁目ごとの値（人口、標高など） |
| `facilities` | facility_id, type, name, lat, lng, snapshot_id, first_seen, last_seen | 薬局などの点 |
| `recipe_results` | recipe_id, area_code, computed_at, score, detail_json | レシピの計算結果 |

- 取得日つきで残すので、施設の開設・閉院を後から差分で追える。
- 全国化で10GBに近づいたら、pref_code で D1 を分割する。キーに都道府県を含めているのはそのため。
- 個人情報は持たない。

## 6. API（案）

| パス | 返すもの |
|---|---|
| `GET /layers` | レイヤー一覧とメタ情報 |
| `GET /areas?bbox=` | 範囲内の町丁目と指定レイヤーの値 |
| `GET /facilities?type=&bbox=` | 範囲内の施設 |
| `GET /recipes` | レシピ一覧 |
| `GET /recipes/{id}/results?pref=&limit=` | レシピの上位結果 |
| `GET /tiles/{name}.pmtiles` | 町丁目ポリゴン（R2 から範囲リクエストで配信） |

## 7. 画面

スマホで片手で見る前提。
- 地図に町丁目を色分け表示。レシピを切り替える。
- しきい値（距離、標高差など）をスライダーで動かす。
- 町丁目を押すと、下からシートで内訳を出す。
- 上位20か所の一覧から地図へ飛ぶ。

## 8. レシピ第1号：受渡店舗の候補地

- 行きにくさ：最寄りの OTC 販売店まで 500m 以上、または標高差 20m 以上（しきい値は仮置き）。
- 行きにくい町丁目を、75歳以上人口の多い順に並べる。
- 崩れる条件：行きにくい町丁目の75歳以上人口がどこも100人未満なら、この地域に需要地はないと判断する。
- 未確認事項：ドラッグストア（店舗販売業）の所在地データ。医療情報ネットは薬局のデータなので、
  これが無いと空白を過大に見積もる。兵庫県・大阪府・各市の公開データを先に調べる。
- 限界：直線距離は道路距離より短く出る。

## 9. 段階

| 段階 | 内容 | 終わりの条件 |
|---|---|---|
| 0 | データの実在確認（特にドラッグストア）、Cloudflare のプラン確認 | 使う原本の URL と項目が一覧になっている |
| 1 | 境界＋人口＋薬局の3層を地図に出す（明石・神戸・西宮） | スマホで地図が開き、町丁目を押すと値が出る |
| 2 | 標高とレシピ機能。受渡店舗の上位20か所 | 上位20か所の表が出て、5か所を目視で検算できる |
| 3 | 大阪府＋兵庫県へ拡大。差分観測と地価 | 2回目の取得で開設・閉院の差分が出る |
